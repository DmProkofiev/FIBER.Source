# Обзор и рефакторинг — этап 1

## Область проверки

Проверены запуск/DI/завершение приложения, сервисы CRUD и связей, контексты EF и конфигурация SQLCipher, импорт/экспорт и временные файлы, загрузка карточек/настроек, аудио-, видео- и Zoom-плееры. Выполнен поиск блокирующих файловых операций и обращений к EF из ViewModel. Схема сущностей не менялась.

## Выявленные проблемы и исправления

| Проблема | Исправление |
|---|---|
| SQLite выполняет async-вызовы синхронно на вызывающем потоке | Границы сервисов переводят выполнение на пул потоков через `BackgroundWork`. ViewModel возвращается в UI-контекст после await. Миграции также выполняются вне Dispatcher. |
| EF-запросы прямо в `SettingsViewModel` | Выделен `ISettingsDataService`/`SettingsDataService`, возвращающий DTO. ViewModel отвечает за состояние экрана; устаревшие результаты загрузки игнорируются. |
| Декодирование файловых изображений в конструкторе VM | Асинхронное чтение, фоновое декодирование, ограничение параллелизма, защита от повторной загрузки и публикации после Dispose. В настройках картинки загружаются при создании видимого элемента. |
| Предзагрузка всех видео/аудио при запуске и открытии хранилища | Кэшируются только метаданные. Видео/аудио извлекаются при загрузке контрола. Каждая VM владеет отдельным временным файлом. |
| Чтение больших BLOB целиком при извлечении/экспорте/удалении | Извлечение и экспорт используют incremental `SqliteBlob` + `CopyToAsync`; удаление выполняется SQL-командой. После сохранения вложения его BLOB отсоединяется от ChangeTracker. |
| Старая строка подключения после `PRAGMA rekey` | `RuntimeDbContextFactory` читает текущий пароль при создании контекста. `DatabaseAccessCoordinator` исключает смену ключа при живых контекстах. Старые пулы очищаются; новый ключ проверяется повторным открытием. |
| Копирование работающего файла WAL-базы | Оба вида экспорта используют `sqlcipher_export`, промежуточный файл и замену результата. Запрещено экспортировать поверх рабочей БД. Повторный экспорт проверен. |
| Общее сообщение EF скрывает причину сохранения | Ошибка содержит код SQLite, расширенный код и исходное сообщение ограничения. FK/UNIQUE/CHECK/NOT NULL различаются. Это позволяет отличить ошибки данных от проблем чтения зашифрованных страниц. |
| Частичное создание/изменение персоны или организации при ошибке связей | Сохранение сущности и её связей объединено транзакцией. Исправлено отсутствие финального сохранения участия персоны в событиях при создании. |
| Изменение/удаление участия персоны и компании в событиях не применялось | При редактировании загружаются необходимые навигационные коллекции. Проверяются повторяющиеся события во входном наборе. |
| Пакет одинаковых вложений создавал повторные связи | Дедупликация пакета по хэшу и транзакция импорта. Отсутствующий временный файл приводит к явной ошибке, а не молчаливому пропуску. Хэш вычисляется по сохранённой копии. |
| Очистка каждые 10 минут удаляла несохранённые/воспроизводимые файлы | Отдельный каталог текущей сессии. Периодическая очистка обрабатывает предыдущие сессии. Явное удаление и завершение выполняются асинхронно. |
| Фоновое обслуживание стартовало одновременно с миграциями | Хост запускается после миграций. Добавлены `cipher_integrity_check`, `quick_check`, `foreign_key_check`. Очистка связей/осиротевших BLOB выполняется транзакционно. |
| Таймер позиции перезаписывал пользовательский seek до окончания debounce | Общие `SeekDebouncer` и `MediaControlPlayback`: сохранение последнего значения, один таймер, запрет фонового обновления слайдера при ожидающей перемотке, отмена при Stop/Unload/смене файла. Используются и в Zoom. |
| Программное обновление позиции VM запускало перемотку | Разделены программное обновление и пользовательский ввод. Отложенный Play отменяется при Pause/Stop; Dispose всегда закрывает плеер и таймеры. |
| `IsPlaying` определялся по позиции и оставался true на паузе | Состояние воспроизведения обновляется явно при Play/Pause/Stop/Ended/Failed. |
| Асинхронные ответы старой карточки могли перезаписывать новую | Версия выбора в `SearchViewModel`, локальное накопление связей и проверка актуальности перед публикацией. |
| Дублирование конвертации DTO, удаления временных списков и управления слайдером | Общие методы конвертации/очистки и общий контроллер воспроизведения. |

## Проверки

- Исходная сборка: 0 ошибок, 0 предупреждений.
- Исходные тесты: 72 пройдено, 6 падали (`MediaImportTests`, NullReference при извлечении файла).
- Итог: сборка без ошибок и предупреждений; **85/85 тестов пройдено**, включая интеграционные проверки SQLCipher и WPF Dispatcher.
- Проверяются: миграции новой зашифрованной БД, неверный пароль, rekey, ожидание живого DbContext, запись после смены ключа, побайтовая сохранность BLOB, зашифрованный/открытый и повторный экспорт, запрет экспорта поверх оригинала, откат неудачного создания, CRUD участия в событиях, раскрытие SQLite CHECK-ошибки, debounce и его отмена, отсутствие перезаписи seek таймером, возврат вызывающего кода на Dispatcher.
- UI smoke через Windows UI Automation на отдельной копии сборки с новой БД: ввод пароля, создание базы, миграции, главное меню, открытие настроек; окно отвечало на запросы. Тестовая копия удалена.

## Границы подтверждённого результата

Ошибка из пользовательской БД не воспроизведена на её конкретных записях: копия проблемной базы и внутреннее исключение не предоставлены. Сообщение `An error occurred while saving the entity changes` само по себе не свидетельствует о нерасшифровываемой записи: SQLCipher шифрует страницы базы, а EF также выдаёт это сообщение при нарушении ограничений данных.

Проверки SQLCipher выполнены на временных базах, воспроизведение и debounce — на уровне Dispatcher/контроллера. Проигрывание реальных аудио/видео с установленными пользовательскими кодеками и измерение задержек на большой рабочей базе требуют отдельного прогона. Итоговая сборка и тесты подтверждают перечисленные сценарии, а не отсутствие любых возможных дефектов во всём приложении.
