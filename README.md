# FIBER Source

> Локальная база знаний о людях, организациях и событиях - в одном зашифрованном файле.

FIBER Source - приложение для Windows, в котором личность, организация
и событие - не изолированные карточки, а узлы единой сети связей.

Родственные и деловые отношения, участие в событиях, алиасы, медиафайлы и заметки
складываются в целостную картину. Все это хранится локально, в едином
зашифрованном файле базы данных fiber.db, защищенном паролем: без облака, без внешних
сервисов и без разрозненных папок с данными.

## Возможности

### Личности
- Два состояния записи: анонимная (известен только псевдоним) и идентифицированная (известны фамилия и имя).
- Полная карточка: ФИО (Фамилия, Имя, Отчество), пол, дата рождения, паспорт, телефон, почта, город и страна, профессия, автомобиль, соцсети, адрес, заметки.
- Алиасы: официальное имя, ник, кличка, псевдоним; управляются пользователем вручную.
- Редактирование в GUI: при редактировании идентифицированной личности или идентификации анонима доступны отдельные поля LastName (Фамилия), FirstName (Имя), SecondName (Отчество).

### Организации
- Название, регистрационный номер, адрес, телефон, почта, сайт и заметки.
- Взаимодействия между организациями и участие в событиях.

### События
- Название, дата, описание, заметки и организаторы (личность или организация).
- Участники с ролями: организатор, соорганизатор, спикер, гость, наблюдатель, спонсор, свидетель, подозреваемый и другие.
- Для каждого участия указываются заметки и контекст.

### Связи
- Человек <-> Человек: родство, дружба, коллеги, партнеры, наставничество, соседство и другие виды отношений.
- Для родственных и деловых связей автоматически создается зеркальная обратная запись (родитель -> ребенок, наставник -> подопечный).
- В карточке отображаются вид связи и пояснения к ней.
- Переход по связи открывает карточку связанного объекта, а кнопка "Назад" возвращает по истории маршрута.

### Поиск
- Отдельные стратегии поиска: по ID, по ФИО, по ФИО + дате рождения, по паспорту, по телефону, по алиасу.
- Поиск по трем вкладкам: личности, организации, события.
- Запуск поиска - кнопкой "Найти"; найденную запись можно сразу открыть, отредактировать, экспортировать или удалить.

## Стратегии поиска дубликатов

В приложении реализован поиск дубликатов на основе паттерна "Стратегия" (IComparisonStrategy).
Каждая стратегия сравнивает две персоны (исходную запись и кандидата) и вычисляет оценку схожести (Score) в диапазоне от 0.0 до 1.0 (0% - 100%).

### 1. Точное совпадение (ExactMatchStrategy)

Стратегия строгой идентификации по ключевым юридическим и персональным данным. Возвращает строго 1.0 или 0.0 без промежуточных оценок.

Как работает алгоритм:
- Сравнение по паспорту: если у обеих персон заполнен номер паспорта, они сравниваются без учета регистра и пробелов. При совпадении возвращается 1.0. Если паспорта заполнены у обоих, но не совпадают, возвращается 0.0.
- Сравнение по ФИО и дате рождения: если паспорта не заданы, проверяются обязательные поля LastName (Фамилия), FirstName (Имя) и BirthDate (Дата рождения). Каждое из этих полей должно быть непустым у обеих сторон.
- Отчество (SecondName) является опциональным: совпадает, если оба значения идентичны (без учета регистра) или оба отсутствуют.
- При полном совпадении Фамилии, Имени, Отчества и точной даты рождения (день, месяц, год) возвращается 1.0.
- Анонимные записи (у которых FullName равно null) точным совпадением не идентифицируются, для них возвращается 0.0.
- Совпадение пустых значений (null == null) никогда не считается совпадением.

### 2. Нечеткое сравнение (LevenshteinStrategy)

Стратегия выявления дубликатов с опечатками, транслитерацией или вариациями написания имени, комбинированная с анализом даты рождения.

Как работает алгоритм:
- Определение имени: для идентифицированной персоны используется полное ФИО (FullName); для анонимной персоны берется значение основного псевдонима (PrimaryAlias).
- Нормализация строк: текст очищается от краевых пробелов, приводится к нижнему регистру, а множественные внутренние пробелы сворачиваются в один.
- Расстояние Дамерау-Левенштейна: вычисляется минимальное количество операций вставки, удаления, замены и транспозиции (перестановки двух соседних символов), необходимых для превращения одного имени в другое.
- Базовая оценка имени: nameScore = 1.0 - (расстояние / max(длина_A, длина_B)).
- Множитель по дате рождения (factor):
  * Обе даты рождения совпадают (разница 0 дней): factor = 1.0
  * Разница дат рождения составляет не более 365 дней: factor = 0.9
  * Разница дат рождения более 365 дней: factor = 0.3
  * У одной персоны дата задана, у другой отсутствует: factor = 0.5
  * У обеих персон даты рождения не заданы: factor = 0.3
- Итоговый результат: Score = nameScore * factor (с ограничением от 0.0 до 1.0).

### 3. Сравнение по метаданным (MetadataStrategy)

Стратегия взвешенного сопоставления контактных данных, адресов и метаданных. Применяется, когда ФИО неизвестно, искажено или персоны анонимны, но имеют общие контакты.

Как работает алгоритм:
- Сравнение проводится только по тем полям, которые заполнены у обеих персон.
- Каждому полю назначен весовой коэффициент в зависимости от его уникальности:
  * Паспорт (Passport): вес 5.0 (сравнение без учета регистра)
  * Телефон (Phone): вес 3.0 (сравнение строго по цифрам, игнорируя форматирование +7/8/скобки/дефисы)
  * Email (Mail): вес 3.0 (сравнение без учета регистра)
  * Адрес (Address): вес 1.5 (сравнение без учета регистра)
  * Соцсети (SocialMedia): вес 1.5 (сравнение без учета регистра)
  * Автомобиль (Car): вес 1.0 (сравнение без учета регистра)
  * Город (City): вес 0.5 (сравнение без учета регистра)
  * Профессия (Job): вес 0.5 (сравнение без учета регистра)
  * Код страны (CountryCode): вес 0.3 (сравнение без учета регистра)
- Формула расчета: Score = сумма весов совпавших полей / сумма весов сравнимых полей.
- Защита от ложных срабатываний: если у персон совпало только одно сравнимое поле (например, только город или только телефон), итоговый Score ограничивается значением 0.5. Если сравнимых полей нет вовсе, Score равен 0.0.

## Какой результат получает пользователь

1. Пользователь нажимает кнопку "Дубликаты" на вкладке "Личности" в разделе поиска.
2. Открывается окно "Поиск дубликатов", где пользователь выбирает:
   - Одну из трех стратегий сравнения (Точное совпадение, Нечеткое сравнение, Сравнение по метаданным).
   - Порог отсечения схожести от 0% до 100% с шагом 5% (по умолчанию 60%).
3. По нажатию кнопки "Искать" сервис в фоновом потоке выполняет сравнение исходной персоны со всеми остальными записями базы данных.
4. Пользователь видит таблицу кандидатов, отсортированную по убыванию процента совпадения. В таблице отображаются:
   - Процент совпадения (ScoreText)
   - Идентификатор записи (ID)
   - Имя / ФИО / Псевдоним (DisplayName)
   - Дата рождения (BirthDate)
   - Пол (GenderText)
5. Двойной клик по строке кандидата закрывает окно и открывает карточку выбранного человека в режиме просмотра в основном окне.
6. Переход автоматически сохраняется в маршруте навигации: кнопка "Назад" позволяет мгновенно вернуться к исходной записи.

## Медиа
- Изображения, видео и аудио хранятся внутри базы данных в виде бинарных BLOB-данных.
- Дедупликация по хэшу SHA-256: одинаковый файл не дублируется, создается только ссылка MediaAttachmentLink.
- Картинки декодируются и отображаются напрямую из оперативной памяти без сохранения на диск.
- Видео и аудио воспроизводятся через временную директорию %Temp%\FIBER\, которая автоматически очищается фоновой службой и при выходе.
- Медиафайлы можно связывать одновременно с несколькими персонами, организациями и событиями.

## Экспорт
- Выгрузка карточек в форматы Word (.docx) и текст (.txt).
- Прикрепленные медиафайлы экспортируются вместе с документом в целевую папку.

## Безопасность и настройки
- Авторизация по паролю при старте (AES-256 через SQLCipher).
- Смена пароля базы данных с перешифровкой файла (PRAGMA rekey).
- Экспорт резервной копии базы данных (в зашифрованном или расшифрованном виде).
- Журнал аудита действий (AuditLogEntry).
- Защита данных: режим журнала WAL, атомарные транзакции, включенные внешние ключи.
- Фоновая служба StorageMaintenanceService проверяет целостность БД и очищает временные файлы.

## Архитектурные принципы

- SOLID: Стратегии поиска и сравнения изолированы и создаются через фабрики. Добавление новой стратегии не требует изменения существующих классов.
- DRY: Логика каскадного удаления и очистки медиа инкапсулирована в базовом и целевых сервисах.
- KISS: Простые и понятные контракты без избыточных универсальных обобщений.
- Чистая архитектура: Вся бизнес-логика и валидация находятся в сервисах. ViewModels отвечают за состояние интерфейса, Views - за визуальное представление.
- Асинхронность и отзывчивость GUI: Все операции ввода-вывода с базой данных и файлами выполняются асинхронно, декодирование изображений вынесено в фон, исключены блокирующие вызовы.
