# FIBER Source

> Локальная база знаний о людях, организациях и событиях - в одном зашифрованном файле.

**FIBER Source** - приложение для Windows, в котором личность, организация
и событие - не изолированные карточки, а узлы одной живой сети связей.

Родственные и деловые отношения, участие в событиях, алиасы, медиафайлы и заметки
складываются в целостную картину. Всё это хранится **локально**, в **едином
зашифрованном файле** БД, защищенном паролем: без облака, без внешних
сервисов и без разрозненных папок с данными.

## Возможности

### Личности
- Два состояния записи: **анонимная** (известен только псевдоним) и **идентифицированная** (известны фамилия и имя).
- Полная карточка: ФИО, пол, дата рождения, паспорт, телефон, почта, город и страна, профессия, автомобиль, соцсети, адрес, заметки.
- **Алиасы** - официальное имя, ник, кличка, псевдоним; управляются пользователем вручную.

### Организации
- Название, регистрационный номер, адрес, телефон, почта, сайт и заметки.
- Участие в событиях связывает организацию с людьми и другими организациями.

### События
- Название, дата, описание, заметки и организатор - личность или организация.
- Участники с ролью: организатор, соорганизатор, спикер, гость, наблюдатель, спонсор, свидетель, подозреваемый и другие.
- Для каждого участия можно указать пояснение - контекст важнее сухой должности.

### Связи
- **Человек <-> Человек:** родство, дружба, коллеги, партнеры, наставничество, соседство и другие виды отношений.
- Для родственных и деловых связей автоматически создается **обратная запись** (родитель -> ребенок, наставник -> подопечный).
- В карточке видно не только вид связи, но и **пояснение** к ней.
- Переход по связи открывает карточку связанного объекта, а кнопка **Назад** возвращает по истории просмотра.

### Поиск
- Отдельные стратегии поиска: по ID, по ФИО, по ФИО + дате рождения, по паспорту, по телефону, по алиасу.
- Поиск по трем вкладкам: личности, организации, события.
- Запуск поиска - кнопкой "Найти"; найденную запись можно сразу открыть, отредактировать, экспортировать или удалить.

### Поиск дубликатов

Поиск дубликатов работает на трех стратегиях сравнения. Каждая стратегия принимает двух
персон (источник и кандидата) и возвращает число от 0.0 до 1.0: чем больше число, тем сильнее
кандидат похож на источник.

**Точное совпадение** проверяет идентифицирующие поля и возвращает либо 1.0 (совпадение есть),
либо 0.0 (совпадения нет):
- совпал паспорт (оба поля непустые) - 1.0, разные паспорта - 0.0;
- ФИО и дата рождения совпали, отчество опционально, дата должна совпасть - 1.0;
- персоны должны быть идентифицированы, анонимы с FullName = null не сравниваются.

**Нечёткое сравнение (Левенштейн)** вычисляет расстояние Дамерау-Levenshtein между именами
(для идентифицированной персоны имя собирается из ФИО, для анонима - основной псевдоним).
Сначала вычисляется nameScore = 1 - (расстояние / max(len(a), len(b))). Затем score умножается
на factor, который учитывает дату рождения: даты равны - 1.0, разница до года - 0.9,
больше года - 0.3; обе даты не заданы - 0.3, одна дата не задана - 0.5.

**Сравнение по метаданным** взвеширует совпадения по контактным и персональным полям:
паспорт (вес 5), телефон (3), почта (3), адрес (1.5), соцсети (1.5), транспорт (1),
город (0.5), профессия (0.5), страна (0.3). Поле учитывается только если оно заполнено
у обеих персон. score = сумма весов совпавших полей / сумма весов сравнимых полей.
Если совпало только одно поле, score ограничен 0.5.

- **Порог отсечения** выбирается пользователем из диапазона 0-100% (шаг 5%, по умолчанию 60%).
- Таблица кандидатов показывает Id, имя, дату рождения, пол и процент совпадения.
- Двойной клик по строке открывает найденную запись; переход учитывается в истории,
  поэтому "Назад" возвращает к исходной карточке.

**Результат для пользователя:** вкладка "Поиск" содержит кнопку "Дубликаты". Пользователь
выбирает одну из трех стратегий, задает порог и запускает поиск. Окно показывает список
кандидатов, отсортированный по убыванию процента совпадения. Двойной клик по строке
открывает кандидата в карточке; кнопка "Назад" возвращает к исходной записи.

### Медиа
- Изображения, видео и аудио хранятся **внутри базы данных** в виде BLOB.
- Дедупликация по **SHA-256**: одинаковый файл не дублируется, создается только новая связь с владельцем.
- Картинки показываются из памяти, без временных файлов; просмотр - с увеличением.
- Видео и аудио воспроизводятся через временный файл в `%Temp%\FIBER\`, который удаляется автоматически.
- Один медиафайл можно прикрепить к нескольким личностям, организациям и событиям.

### Экспорт
- Выгрузка карточки личности, организации или события в отдельную папку.
- Форматы: **Word (.docx)** и **текст (.txt)**.
- Вместе с отчетом экспортируются выбранные медиафайлы.

### Безопасность и настройки
- Пароль запрашивается при запуске и расшифровывает базу на лету.
- **Смена пароля** с перешифровкой всего файла.
- **Экспорт резервной копии** - зашифрованной или расшифрованной.
- **Журнал событий** приложения.
- Защита от повреждения: режим **WAL**, атомарные транзакции, внешние ключи.
- Фоновая служба при старте проверяет целостность данных и удаляет осиротевшие медиассылки, а каждые 10 минут очищает временные файлы.
- Приложение работает в одном экземпляре; иконка доступна в системном трее.

## Архитектура

Приложение построено по слоям - от контрактов и моделей до сервисов и представлений
Бизнес-логика и валидация живут в сервисах, а не во ViewModel или XAML

```
FIBER.Source/
├── Contracts/        входные модели и сводки (Inputs, Summaries)
├── Models/           сущности EF Core, перечисления, связующие таблицы, хелперы
├── Interfaces/       контракты сервисов и стратегий
├── Services/         бизнес-логика: CRUD, связи, медиа, экспорт, аудит
│   ├── Search/       стратегии поиска (ISearchStrategy)
│   └── Comparison/   стратегии сравнения дубликатов (IComparisonStrategy)
├── Infrastructure/   DbContext, конфигурации EF Core, хостинг
├── Migrations/       миграции базы данных
├── ViewModels/       состояние экранов и команды
├── Views/            окна и пользовательские элементы WPF
├── Helpers/          конвертеры, уведомления, вспомогательные типы
└── Resources/        иконки, фон и графика приложения
```

**Ключевые решения**

- **DI через хостинг.** Все сервисы, ViewModel и стратегии регистрируются в `App.xaml.cs`; `DbContext` создается через `AddDbContextFactory`.
- **Стратегии вместо ветвлений.** Поиск и сравнение расширяются новой реализацией интерфейса и одной строкой регистрации в DI.
- **Тонкие ViewModel.** Экраны вызывают сервисы и хранят состояние; правила предметной области остаются в сервисах.
- **Асинхронный ввод-вывод.** Операции с базой и файлами выполняются без блокировки интерфейса.
- **Навигация с историей.** Переходы по связям и дубликатам складываются в маршрут, поэтому "Назад" всегда предсказуем.
